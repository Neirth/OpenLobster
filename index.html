What changed

Every OpenClaw flaw, addressed.

OpenClaw had a moment — self-hosted AI agent, fast growth, lots of attention. Then the security community looked at it. CVE-2026-25253 (CVSS 8.8): 1-click RCE via querystring injection in the control UI. CVE-2026-25593, CVE-2026-24763, CVE-2026-25157, CVE-2026-25475, and more filling a full page on RedPacket. Cisco published a report calling personal AI agents like OpenClaw a security nightmare. Microsoft's Security Blog recommended running it only inside an isolated VM with a dedicated non-privileged account. By February 2026, 40,000 exposed instances were indexed on Censys — 63% of them vulnerable to remote code execution.

Beyond security: the memory system was a MEMORY.md file. The scheduler was a heartbeat daemon waking up every 30 minutes to read a checklist. There was no concept of separate users — the docs listed "only the main session writes to MEMORY.md" as a feature. The skills marketplace shipped 26% of entries with at least one vulnerability.

OpenLobster is the fork that addresses the list. Not a rebranding — a rewrite of every part that was broken, starting with the assumption that security is not optional.

01

Security by default

Dashboard auth is enforced before first launch, not an opt-in flag. Config and secrets are encrypted on disk. API keys live in a secrets backend — encrypted file or OpenBao — never in plain YAML. Env vars with the OPENLOBSTER_ prefix are never forwarded to terminal tools.

CVE-hardened

02

Graph memory

MEMORY.md does not scale and does not reason about relationships. OpenLobster uses Neo4j as a first-class graph database: typed nodes, typed edges, and relationship weights the agent builds and updates as it converses. A file-based GML backend is available for single-node setups where running Neo4j is impractical.

Neo4j or file backend

03

First-class multi-user

Each user on every channel is a separate entity: own conversation history, own tool permissions, own pairing flow. A Telegram user and a Discord user can talk to the same agent simultaneously without sharing context or stepping on each other's sessions.

Per-user permissions

04

Real task scheduler

The 30-minute heartbeat loop reading a HEARTBEAT.md checklist is removed. Recurring jobs use cron expressions. One-shot tasks use ISO 8601 datetimes. Status, next-run time, and execution logs are visible in the dashboard without touching a config file.

Cron + ISO 8601

05

Full MCP integration

Any Streamable HTTP MCP server works: OAuth 2.1 is handled end-to-end, tool browsing is per-server, and each user gets an explicit permission matrix so you control exactly what they can invoke. A one-click marketplace covers the most common integrations.

OAuth 2.1 + per-user matrix

06

Go backend, single binary

The entire Node.js backend has been rewritten in Go with a GraphQL API generated by gqlgen. The output is a single static binary with no runtime dependency. 200 ms cold start. 30 MB RAM. Runs on a Raspberry Pi 3, a VPS with 512 MB, or a $15 LicheeRV Nano.

Go + gqlgen

Comparison

How OpenLobster positions in the landscape.

The Claw family and the broader self-hosted AI agent ecosystem share overlapping goals but make very different trade-offs. OpenClaw, PicoClaw, and NanoClaw are direct architectural relatives. Quick start

Running in under two minutes.

Build from source or pull the Docker image. No Node, no npm, no node_modules. A single binary and a config file is all it takes.

build from source 
# Requires Go 1.22+ and pnpm
pnpm install
pnpm build --filter=@openlobster/backend

# Dashboard at http://127.0.0.1:8080
./dist/openlobster
docker 
docker run -p 8080:8080 \
  -e OPENLOBSTER_GRAPHQL_HOST=0.0.0.0 \
  -e OPENLOBSTER_GRAPHQL_AUTH_TOKEN=your-secret \
  -v ~/.openlobster/data:/app/data \
  ghcr.io/neirth/openlobster/openlobster:latest
minimal environment variables 
# Agent identity
OPENLOBSTER_AGENT_NAME=my-agent

# Database — SQLite for local use
OPENLOBSTER_DATABASE_DRIVER=sqlite
OPENLOBSTER_DATABASE_DSN=./data/openlobster.db

# Auth — set before exposing to the network
OPENLOBSTER_GRAPHQL_AUTH_TOKEN=strong-secret

# Memory — file backend, no Neo4j required
OPENLOBSTER_MEMORY_BACKEND=file
OPENLOBSTER_MEMORY_FILE_PATH=./data/memory

# AI provider — pick one
OPENLOBSTER_PROVIDERS_OLLAMA_ENDPOINT=http://localhost:11434
# or
OPENLOBSTER_PROVIDERS_ANTHROPIC_API_KEY=sk-ant-…
# or
OPENLOBSTER_PROVIDERS_OPENAI_API_KEY=sk-…

Stack

Boring technology, deliberately.

No framework churn. Each choice was made to reduce operational overhead and keep the binary small enough to run at the edge.

Frontend SolidJS + Vite, vanilla CSS — no component framework
Backend Go, GraphQL API generated by gqlgen — single static binary
Database SQLite (default), PostgreSQL, or MySQL
Memory File backend (GML) for local use, or Neo4j for multi-instance
Secrets Encrypted file backend, or OpenBao for production
Channels Telegram, Discord, WhatsApp Business, Slack, Twilio SMS
AI providers OpenAI, Anthropic, Ollama, OpenRouter, Docker Model Runner, any OpenAI-compatible endpoint
